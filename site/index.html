Perch

A menu bar app that tells you when a Claude Code session is waiting on you.

Download for macOS View source

Free and open source (MIT). Needs macOS 15 or later. Runs on Apple Silicon and Intel.

I left a session waiting for 32 hours

It was sitting on a permission prompt, behind a fullscreen window, in a terminal tab I'd forgotten about. That's why I wrote this.

Perch reads the files Claude Code already writes to your disk and keeps a summary in your menu bar, so you can glance up and see what's running and what's stuck.

You'll know when something is stuck

Every session shows as working, idle, or waiting on you, with the terminal it belongs to. You can have Perch notify you once when a session has been waiting longer than you're happy with. Some projects are fine to leave sitting, so you can set a different limit on those, or turn it off for them entirely.

Where the tokens went

Totals by project and by model, over whatever window you care about, plus a two week chart on every project card. If a model isn't in the price table, Perch counts its tokens and tells you it doesn't know what they cost. It won't put a zero there and let you think that's the answer.

Getting back into a project

Each project keeps its README blurb, whatever notes you've added, and every session you've run in it. Resume picks an old session back up, and there's a button to start a fresh one. Either way it opens in the right folder, in the terminal you actually use. Terminal, iTerm2, Warp, Ghostty, Alacritty, Kitty and WezTerm all work.

Nothing leaves your Mac

Your transcripts have your source code in them, and probably a few things you pasted in without thinking too hard about it. So Perch doesn't send them anywhere. It doesn't send anything anywhere.

  • There's no network code No HTTP library anywhere in the build, no sockets in the source. The build fails if anyone adds one, or writes an http:// address into the app at all.
  • No analytics, no crash reports There's no setting to turn off. It was never there in the first place.
  • It doesn't write to your Claude Code folder Perch only reads it. Its own database and settings live somewhere else, in a folder of its own. The build fails if a file-writing call turns up where it shouldn't be.
  • It doesn't keep what it reads Perch counts tokens and works out what state a session is in. What your conversations actually say never reaches a window, a notification, a log file, or the MCP server.

The whole app pulls in 153 packages, all of them MIT licensed and on GitHub. If you'd rather check any of this yourself than take my word for it, that's a small enough pile to actually get through.

Claude Code can ask it things

There's a small MCP server inside the app. Register it and you can ask Claude Code about your own projects and usage: 

claude mcp add --scope user perch -- /Applications/Perch.app/Contents/MacOS/perch-mcp

Four tools: list your projects, look one up, see what's running, and get a usage summary. It opens the database in read-only mode, so it can't write to it even by accident, and like the rest of the app it has no network code in it.

Installing it

  1. Download the latest release, unzip it, and drag Perch into your Applications folder.
  2. The first time you open it, macOS will stop you. I haven't paid Apple $99 a year for a developer certificate, so as far as your Mac is concerned Perch comes from a stranger. To get past it: open System Settings, go to Privacy & Security, scroll to the bottom, and click Open Anyway.
  3. After that it should just work. Perch finds your Claude Code folder on its own, and if it guesses wrong you can point it at the right one in Settings.

On macOS 15 that second step is the only way in. Right-clicking and choosing Open used to work, and doesn't any more. And if you'd rather not run an unsigned binary you downloaded from someone's website, that seems fair enough to me, given what this thing reads. Building it yourself is two commands and the README walks through it.
