Perch

A macOS menu-bar dashboard for Claude Code: which sessions are working, which are waiting on you, and what they cost.

Download for macOS View source

Free and open source (MIT). Requires macOS 15+. Universal — Apple Silicon and Intel.

A session waited 32 hours and nobody noticed

That's the bug Perch was written for. If you run more than one Claude Code session, they scroll off, get buried behind a fullscreen window, and sit quietly on a permission prompt. Perch reads what Claude Code already writes to disk and puts the answer in your menu bar.

Know which session is stuck

Working, idle, or waiting on you — and which terminal owns it. Turn on the notification and Perch tells you once per episode when a session has been waiting longer than you're willing to let it, with a per-project override for the ones that are allowed to sit.

See where the tokens went

Per project and per model, over whatever window you pick. Fourteen days of token-class bars, a top-projects ranking, and a sparkline on every project card. A model with no price contributes its tokens and is named as unpriced — never quietly counted as $0.

Pick up where you left off

Every project, with its README description, session history and your own notes. Resume an ended session or start a fresh one in the project's own directory, in your terminal — Terminal, iTerm2, Warp, Ghostty, Alacritty, Kitty and WezTerm.

Your transcripts stay yours

Transcripts contain source code, pasted secrets and client names. An app that reads them owes you more than a promise, so these are enforced by the build:

  • No network requests. No HTTP client in the dependency graph, no socket in the source. CI fails the build if either changes, or if any line of Rust or Swift names an absolute http(s):// URL.
  • No telemetry, analytics or crash reporting. Not off by default. Absent.
  • Read-only. Perch never writes to, moves or deletes anything in your Claude Code directory. CI fails the build if a filesystem-writing call appears anywhere it shouldn't.
  • No transcript contents leave the parser. Perch reads transcripts to count tokens and detect state. No message text reaches a window, a notification, a log line or the MCP server.

153 packages in the dependency graph, all of it MIT-licensed and on GitHub. It's a small enough pile that a suspicious person can check these claims in an afternoon, which is the point.

Claude Code can ask Perch things

Perch ships a read-only MCP server inside the app bundle, so Claude Code can query your own projects, live sessions and usage. 

claude mcp add --scope user perch -- /Applications/Perch.app/Contents/MacOS/perch-mcp

It opens the index read-only at the SQLite level — writes are refused by the connection itself, not merely avoided — and has no network code at all.

Installing

  1. Download the latest release, unzip it, and drag Perch.app to your Applications folder.
  2. The first launch will be blocked. Perch is signed, but with an ad-hoc signature rather than a paid Apple Developer ID, so macOS treats it as coming from an unidentified developer. Open System Settings → Privacy & Security, scroll to the bottom, and click “Open Anyway”.
  3. That's it. Perch finds your Claude Code directory on its own, and you can correct it in Settings if it guesses wrong.

On macOS 15 that second step is the only route — the old right-click → Open trick no longer works for unsigned apps. Removing it needs a paid Apple Developer account, which this project doesn't have yet. If you'd rather not run an unidentified binary at all, that's a reasonable instinct for an app that reads your transcripts: building from source is two commands.
